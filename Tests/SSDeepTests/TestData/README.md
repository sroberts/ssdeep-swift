# SSDeep Test Data

This directory contains test data and golden reference hashes for validating SSDeep-Swift against the canonical ssdeep 2.14.1 C implementation.

## Overview

The test data is organized into three tiers, providing comprehensive coverage of different scenarios and edge cases:

1. **Essential Test Vectors** (`essential/`) - Core edge cases and basic scenarios
2. **Real-World Corpus** (`real-world/`) - Representative file types from actual usage
3. **Generated Data** (`generated/`) - Fuzzing and boundary case data

## Directory Structure

```
TestData/

├── golden-hashes.txt          # Reference hashes from ssdeep 2.14.1
├── essential/                 # Essential test vectors (11 files, <2 MB)

│   ├── tiny.txt               # 5 bytes - minimal input
│   ├── small.txt              # 100 bytes - small text
│   ├── medium.bin             # 10 KB - medium binary
│   ├── large.bin              # 1 MB - large file
│   ├── repeated.txt           # 1 KB of repeated 'A'
│   ├── binary.bin             # 4 KB random binary
│   ├── utf8.txt               # 500 bytes UTF-8 text
│   ├── null-bytes.bin         # 1 KB of null bytes
│   ├── line-endings-lf.txt    # Unix line endings
│   └── line-endings-crlf.txt  # Windows line endings
├── real-world/                # Real file types (8 files, ~1.5 MB)
│   ├── source.swift           # Swift source code
│   ├── json-data.json         # JSON data
│   ├── log-file.log           # Log file
│   ├── document.pdf           # PDF document
│   ├── image.jpg              # JPEG image
│   ├── executable.macho       # macOS executable
│   ├── executable.elf         # Linux executable
│   └── archive.zip            # ZIP archive
└── generated/                 # Generated test data (created by script)
    ├── random-*.bin           # Random data (various sizes)
    ├── pattern-*.bin          # Pathological patterns
    └── boundary-*.bin         # Boundary cases (powers of 2)
```

## Golden Hashes File

The `golden-hashes.txt` file contains reference hashes generated by ssdeep 2.14.1. Format:

```
# SSDeep Golden Reference Hashes
# Generated: YYYY-MM-DD HH:MM:SS UTC
# SSDeep Version: 2.14.1
# Format: filepath|hash

Tests/SSDeepTests/TestData/essential/empty.bin|3::
Tests/SSDeepTests/TestData/essential/tiny.txt|3:abc:def
...
```

## Regenerating Golden Hashes

**⚠️ IMPORTANT**: Only regenerate golden hashes when **intentionally** updating the algorithm. Never regenerate to "fix" failing tests - fix the implementation instead!

### Prerequisites

Install ssdeep 2.14.1:

```bash
# macOS
brew install ssdeep

# Linux
apt-get install ssdeep
```

Verify version:

```bash
ssdeep -V
# Should output: ssdeep version 2.14.1
```

### Regeneration Steps

1. Ensure all test files exist:
   ```bash
   swift Scripts/generate-test-data.swift
   ```

2. Generate golden hashes:
   ```bash
   ./Scripts/generate-golden-hashes.sh
   ```

3. Verify the hashes:
   ```bash
   git diff Tests/SSDeepTests/TestData/golden-hashes.txt
   ```

4. If changes are intentional, commit both files:
   ```bash
   git add Tests/SSDeepTests/TestData/golden-hashes.txt
   git commit -m "Update golden hashes for [reason]"
   ```

## Adding New Test Files

When adding new test files to the corpus:

1. Add the file to the appropriate subdirectory:
   - `essential/` for core edge cases
   - `real-world/` for representative file types
   - Modify `Scripts/generate-test-data.swift` for generated data

2. Regenerate golden hashes:
   ```bash
   ./Scripts/generate-golden-hashes.sh
   ```

3. Commit both the new file AND updated `golden-hashes.txt`:
   ```bash
   git add Tests/SSDeepTests/TestData/
   git commit -m "Add test case for [scenario]"
   ```

## Test Coverage

### Essential Test Vectors

These files cover fundamental edge cases:

- **Size boundaries**: 0 bytes, 5 bytes, 100 bytes, 10 KB, 1 MB
- **Content types**: Text, binary, UTF-8, null bytes
- **Patterns**: Repeated characters (tests sequence elimination)
- **Line endings**: Unix (LF) and Windows (CRLF)

### Real-World Corpus

Representative file types from actual usage:

- **Source code**: Swift files (text, UTF-8, structured)
- **Data formats**: JSON (structured text)
- **Logs**: Multi-line text with timestamps
- **Documents**: PDF (complex binary format)
- **Images**: JPEG (compressed binary)
- **Executables**: Mach-O (macOS), ELF (Linux)
- **Archives**: ZIP (compressed, multiple files)

### Generated Data

Created by `Scripts/generate-test-data.swift`:

- **Random data**: 1 KB, 10 KB, 100 KB, 1 MB (deterministic PRNG)
- **Pathological patterns**: Alternating bytes, gradual sequences, repeated blocks
- **Entropy cases**: High entropy (random-looking), low entropy (sparse non-zero)
- **Boundary cases**: Powers of 2 (2^10, 2^12, 2^16, 2^20 bytes)
- **Edge cases**: All zeros, all ones

## Version Pinning

This test suite is designed for **ssdeep 2.14.1** specifically. If newer versions of ssdeep are released:

### Option 1: Maintain 2.14.1 Compatibility
Continue testing against 2.14.1 to ensure backward compatibility.

### Option 2: Upgrade to New Version
1. Install new ssdeep version
2. Regenerate golden hashes: `./Scripts/generate-golden-hashes.sh`
3. Update this README with new version number
4. Document any behavioral changes in commit message

### Option 3: Support Multiple Versions
Create separate golden hash files for each version:
- `golden-hashes-2.14.1.txt`
- `golden-hashes-2.15.0.txt`
Update test code to select appropriate reference file.

## CI/CD Integration

In CI, the workflow:

1. Installs ssdeep 2.14.1 (via Homebrew on macOS, apt on Linux)
2. Generates test data using `Scripts/generate-test-data.swift`
3. Runs all tests including `ReferenceCompatibilityTests`
4. **Hard fails** if any hash mismatches are detected

Reference tests are skipped on platforms where subprocess execution is limited (iOS, tvOS, watchOS simulators).

## Troubleshooting

### Test failures after algorithm changes
If you modified the hashing algorithm and tests fail:
1. Verify the changes are intentional and correct
2. Manually test against ssdeep CLI to confirm behavior
3. If correct, regenerate golden hashes and document WHY in commit message

### Missing ssdeep CLI
If `ssdeep` command is not found:
- **Golden hash tests** will still run (using stored hashes)
- **Live CLI tests** will be skipped with `XCTSkip`
- Install ssdeep to enable full test coverage

### Version mismatch warnings
If ssdeep version differs from 2.14.1:
- The script will warn but allow continuation
- Hashes may differ if algorithm changed between versions
- Consider whether version upgrade is intended

### Test data missing
If `golden-hashes.txt` doesn't exist:
- Tests will skip with message: "Run Scripts/generate-golden-hashes.sh first"
- Generate the file before running tests
